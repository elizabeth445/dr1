# Після шостої — приглашение

- Общение и README — русский; интерфейс — украинский.
- Следовать `design.md`: экспериментальная клубная афиша; чёрный/лайм/коралл, Unbounded + IBM Plex. Не возвращать прежние serif, бордо, бежевую айдентику и split hero.
- Данные события — `src/config/eventConfig.ts`; сохранять id и формат локальных RSVP при редизайне.
- Билет — отдельные DOM/SVG-слои; GSAP с cleanup и reduced motion. Проверять промежуточные кадры отрыва.
- Native touch; Lenis только на desktop с единственным ticker. Все действия доступны с клавиатуры.
- RSVP не отправляется; маршрут только с подтверждённым адресом.
- Проверять секции в браузере mobile/desktop; итог: минимум 320, 390, 768, 1024, 1440 px, Playwright/axe, визуальный refinement и production build.

- Не добавлять декоративные eyebrow/overline, нумерацию секций, chapter labels и повторяющиеся мелкие uppercase-подписи. Исключения — явный запрос пользователя или необходимость конкретной концепции. Иерархию строить масштабом, типографикой и пространством.

## Подготовка к GitHub и Vercel

- Общие правила очистки и сохранения истории — в `~/.codex/AGENTS.md`, раздел «Чистота проектов и GitHub»; здесь их не дублировать.
- Для этого проекта пользователь заранее разрешил обычные commit и push в `https://github.com/elizabeth445/dr1.git`, ветка `main`. После каждой успешно завершённой задачи на изменение сайта: обновить локальные файлы, выполнить аудит и подходящие проверки, создать коммит с понятным названием, сразу выполнить push и проверить удалённый SHA. Повторное подтверждение не требуется. Это проектное исключение из общего запрета публикации без отдельной команды; для других репозиториев оно не действует.
- Перед коммитом проверить status и diff, перед отправкой — staged diff, origin и ветку; включать только изменения текущей задачи. Не использовать force push, не удалять историю и не отправлять секреты. При конфликте или ошибке Git сохранить чужие изменения, остановить отправку и сообщить о проблеме. После задачи кратко сообщить по-русски результат проверок, результат push и SHA коммита.
- Если локальный Git не авторизован, использовать подключённый GitHub-плагин для создания коммита и обновления `main` без force, проверяя текущий удалённый SHA. Затем получить опубликованную историю локально; не создавать заранее отдельный локальный коммит при таком способе отправки.
- Проверки проекта: `npm run lint`, `npm run typecheck`, `python3 scripts/check-fonts.py`, `npm run build`. Затем запустить production preview на 5198 и выполнить `PLAYWRIGHT_BASE_URL=http://127.0.0.1:5198 npm test`, включая визуальный контроль обязательных ширин.
- Для Vercel: Vite, установка `npm ci`, сборка `npm run build`, результат `dist`. Agentation доступен только в dev; серверные секреты для текущей статической версии не нужны. Автоматический push не разрешает создание deployment, нового удалённого репозитория или настройку автоматической публикации.
- `output/`, `playwright-report/`, `test-results/`, `dist/` и кэши — воспроизводимые локальные результаты, не исходники. Сохранять действующие лицензии шрифтов и материалы, используемые проверкой украинского алфавита.
